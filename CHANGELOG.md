# Changelog

All notable changes to BrowserX are recorded in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The project is pre-1.0; minor versions may contain breaking changes to configuration keys, the HTTP API, command-line interface and on-disk formats, and each such change is listed here.

## [Unreleased]

Initial development toward 0.1.0. Source-only: no binaries or images are published.

### Added

- **Sessions as leases.** Durable lease records with an identity, an owner, a time-to-live with renewal, an absolute lifetime cap, an idle timeout, a lifecycle state machine (`queued`, `allocating`, `active`, `idle`, `recovering`, `draining`, `lost`, `closed`) and a fencing generation. Every lease change is a compare-and-swap on the expected generation; a lost swap surfaces as `stale_generation`.
- **Controller tokens.** `bxt_` lease tokens, returned once and stored only as SHA-256 digests, compared in constant time; rotated by handoff.
- **Snapshot key rotation.** One active key seals new snapshots; retired keys (`storage.retired_snapshot_key_files`) open older ones.
- **Explicit persistence contracts.** `persistence` is `ephemeral`, `snapshot` or `profile`; there is no boolean "persistent" flag. Snapshots capture cookies, per-origin `localStorage` and open page URLs, sealed with AES-256-GCM (metadata bound as associated data), versioned per profile, written atomically with mode `0600`, pruned to `snapshot_keep`. Profile directories are created with mode `0700` under an exclusive lock.
- **Attach outcomes.** Every attach reports `resumed_same_process`, `restored_from_profile`, `restored_from_snapshot` or `fresh_process`.
- **Recovery.** Health monitor with unresponsive strikes, confirmed browser shutdown (graceful close, then process-group termination), relaunch with bounded attempts, `recovery = "none"` to end a session instead, and startup reconciliation of leases orphaned by a worker restart.
- **Handoff.** Token rotation with generation increment; relay connections bound to the old token are closed.
- **Dedicated and shared isolation.** One Chromium process per session, or one browser context per session in a warm shared browser behind a scoped CDP relay that injects the context into `Target.createTarget`, filters targets and events and refuses context, browser and system commands.
- **Scheduler.** Bounded FIFO admission queue with a deadline, per-owner quotas, `max_browsers`, shared-browser slots, warm pool, retirement by age and by contexts served, reaper and periodic snapshotter.
- **Egress forwarder.** A loopback forwarder per dedicated session: direct dialing with a destination policy that refuses private, loopback, link-local, carrier-grade NAT, multicast, reserved and metadata addresses (with an allow-list), or an upstream `http://`, `https://`, `socks5://` or `socks5h://` proxy with credentials kept out of the browser; plain-HTTP requests are tunnelled so CONNECT-only gateways work; `{session}` and `{generation}` username templates.
- **Launch profiles.** Named browser launch configurations (executable, headless, flags, environment); managed flags cannot be overridden. `{persona_seed}` in flags expands to a stable per-identity number.
- **HTTP API.** `/v1/sessions` (create, list, get, attach, renew, handoff, snapshot, release), `/v1/profiles`, `/v1/launch-profiles`, typed JSON errors with stable codes, and the authenticated `/cdp/{session}/{token}` WebSocket relay.
- **Operations.** Ops listener with `/healthz`, `/readyz` and Prometheus `/metrics`; graceful shutdown on `SIGINT` and `SIGTERM` with final snapshots.
- **Command line.** `browserx serve`, `config check`, `keys new`, `snapshot-key new`, `doctor` and the `session` client commands.
- **Documentation.** Design pages (architecture, sessions and leases, persistence, recovery, handoff, isolation and security, egress) and guides (getting started, configuration, API, CLI, CDP clients, upstream proxy, launch profiles, operations).
- **Repository.** CI with a code-owner authorization gate, linting, hashed public-hygiene checks, secret scanning, dependency policy (`cargo deny`) and a CodeQL and security workflow that runs once the repository is public.
- **AI/LLM-native operation.** The positioning is now *next-generation AI/LLM-native browser pooling, session management, persistence, recovery and handoff for authorized security research*: AI agents can watch, drive and explain BrowserX within limits an operator sets. Models advise and act through scoped tools and never authorize; leases, recovery, egress policy and the host-protection relay policy stay deterministic code, with no model in the data path. See [AI/LLM-native operation](docs/design/ai-llm-native.md).
- **MCP server (`browserx-mcp`, `browserx mcp`).** A Model Context Protocol server (revisions `2025-06-18` and `2025-03-26`) over stdio or streamable HTTP (`--http`, loopback by default, bearer token stored as a SHA-256 digest, constant-time comparison, `Origin` check, bodies bounded to 4 MiB). It talks to a worker through the public API and the operations listener. Read-only monitoring tools are always on (`health`, `pool_status`, `assess`, `list_sessions`, `get_session`, `explain_session`, `explain_error`, `list_launch_profiles`, `list_snapshots`, `capabilities`); `sessions`, `handoff`, `browse`, `interact` and `evaluate` are capabilities the operator enables one by one, and a tool that is not enabled is not listed. Includes `browserx mcp check`, `browserx mcp token new` and `browserx mcp audit verify`. See the [MCP server guide](docs/guides/mcp.md) and [`examples/mcp.toml`](examples/mcp.toml).
- **Session tools for agents.** `create_session` (persistence, isolation, launch profile, profile id, TTL, recovery, a named proxy route from configuration instead of credentials), `renew_session`, `snapshot_session`, `release_session` and `handoff_session` (both need `confirm: true`). The MCP server keeps the lease tokens; sessions it creates are labelled `mcp=true` and only controlled sessions can be browsed.
- **Browsing tools for agents.** The MCP server connects to a session's `cdp_url` itself: `open_page`, `page_snapshot` (accessibility tree with stable element references that interactions re-resolve and refuse when stale), `page_text` (readable Markdown), `screenshot` (PNG, at most 2 MiB), tabs, `go_back`, `go_forward`, `wait_for`, `network_log` and `console_log` (bounded rings per tab), `click`, `type_text`, `press_key`, `select_option`, `scroll`, `hover` and, off by default, `evaluate_js`. When the browser behind a session was recovered, the next call reconnects and says what the recovery outcome means.
- **Deterministic scope and untrusted content.** Navigation is confined to `browse.allowed_origins` and an optional engagement window: refused before the request, enforced on every top-level request including redirect hops while the browser is held at the request, and checked again on the final page. All page-derived text is wrapped in `<untrusted_page_content origin="...">` with the wrapper neutralized inside the text. Lease tokens, CDP URLs, API keys and proxy credentials never reach the model.
- **Hash-chained audit log.** Every tool call is appended to a JSONL log (mode `0600`) with the operator, the authorization note and the engagement id; changing calls write an `intent` entry first and are refused if it cannot be written. `browserx mcp audit verify` finds edited, removed or reordered entries and prints the last hash for external anchoring. Typed text is recorded by length and digest.
- **Explanations and assessment.** `pool_status` and `assess` turn background metric samples into windowed rates, a verdict (`ok`, `saturated`, `degraded`) and graded checks with evidence and remediation; `explain_session` and `explain_error` state what each status, recovery outcome and error code means and which state survived.
- **Optional model endpoint.** `[ai]` (any chat-completions compatible endpoint) enables `summarize_page`, `extract_data` (validated against your JSON Schema) and `diagnose`. Each has a deterministic fallback and reports whether the model was used; the model sees only redacted, wrapped content.
- **Resources and prompts.** `browserx://docs/{sessions,persistence,recovery,handoff,security,egress,mcp}` (bundled into the binary), `browserx://sessions/{id}`, and the prompts `triage_session`, `capacity_review` and `explore_authorized_site`.

### Security

- **Session operations run to completion.** Create, attach, renew, handoff, snapshot, release and profile deletion run in a tracked task, so a client that disconnects mid-call can no longer leak a browser, a context slot, a quota slot or a profile claim, or lose the outcome of a handoff. A profile claim is also released by a drop guard.
- **Stranded leases are reaped.** The reaper now finishes leases left in `draining` or `recovering` (retry the release, release when expired, retry the recovery) instead of holding quota, the profile claim and a browser until restart.
- **Relay authentication is uniform and first.** The relay answers `401` for a wrong token and for an unknown session, decided from a lock-free read before any session state is revealed or the session mutex is awaited; the `/v1` operations check owner and token before queueing on the session too. Opening a relay no longer consumes the pending recovery outcome; only `POST .../attach` does.
- **Time arithmetic saturates.** Lease times saturate at the far future instead of staying unchanged on overflow (which made a huge `idle_timeout_secs` or `max_lifetime` expire the session within a tick). A request's `idle_timeout_secs` may not exceed the maximum lifetime, and configured durations above ten years are rejected.
- **Shared-browser crashes no longer over-launch.** A shared browser that is still launching counts as a candidate, so concurrent recoveries and creates wait for it instead of each starting a browser.
- **Host protection on every relay.** Dedicated relays now parse CDP too (bounded) and refuse what turns the browser against the worker's host: navigation or target creation to `file:`, `filesystem:`, `view-source:`, `chrome:`, `chrome-untrusted:`, `devtools:`, internal `about:` pages and scheme-less URLs; `Target.createBrowserContext` with `proxyServer` or `proxyBypassList` (it bypassed the egress forwarder and its destination policy); `DOM.setFileInputFiles`, dragged host files and `Extensions.*`; `Tracing.*`, `Memory.*`, `SystemInfo.*`, `Browser.close` and `Browser.crash*`. Binary client frames are no longer forwarded. Shared relays apply the same rules. A refused command gets a CDP error and the connection stays open.
- **Downloads are confined.** `Browser.setDownloadBehavior` and `Page.setDownloadBehavior` get `downloadPath` forced to a per-session directory under `<state_dir>/downloads`, which is removed with the session's last relay connection and emptied at startup.
- **Snapshot key leaves the state directory.** The default `storage.snapshot_key_file` is now `./.browserx-keys/snapshot.key`, and a key file inside `storage.state_dir` is rejected at startup, because browsers run as the worker's uid. **Breaking:** move an existing key file out of `state_dir` and update the path.
- **Shared relay hardening.** Page-session traffic is limited to an allow-list of protocol domains (`Tracing`, `Memory`, `SystemInfo`, `Extensions` and unknown domains are refused; `Storage` commands naming another context are refused). Requests are tracked by `(sessionId, id)` with duplicate in-flight ids refused, so a reused id can no longer return an unfiltered `Target.getTargets`. `Target.*` events on page sessions are filtered to the session's context. A foreign attachment from a browser-wide `Target.setAutoAttach` is resumed and detached instead of being left to stall a sibling's popup. Pending entries are purged when a CDP session detaches or its target is destroyed, so unanswered commands cannot disable the relay.
- **Relay and listener limits.** At most `server.max_relay_connections_per_session` (default 4) relay connections per session (`429` beyond); shared-session messages are limited to `server.scoped_relay_max_message_bytes` (default 16 MiB, was 64 MiB); both listeners close connections that do not complete a request head within `server.header_read_timeout_secs` (default 10) and keep at most `server.max_connections` (1024) and `server.ops_max_connections` (64) connections.
- **Upstream proxy address is policy-checked.** The forwarder resolves a tenant-supplied `proxy.url` host once, applies `egress.block_private` / `egress.allow_cidrs` to it and dials only the checked addresses. Every failure to reach the upstream proxy answers the same `502 upstream proxy is unavailable`, so the proxy URL is no longer an oracle for internal hosts and ports. **Breaking:** an upstream proxy on a private or loopback address now needs its range in `egress.allow_cidrs`.
- **Browsers no longer outlive a crash unnoticed.** Every launch writes `<state_dir>/tmp/<browser_id>.json` (owner, pid, process group, start time, user-data directory); the worker sweeps at startup, killing leftover browsers it can verify (process group, exact `--user-data-dir=` argument, start time) and removing stale temporary directories. The process group is signalled before the leader is reaped, so a recycled group id is never hit.
- **Proxy password is scrubbed.** Both lease stores drop `spec.proxy.password` when a lease turns terminal, existing terminal rows are scrubbed on open, and SQLite runs with `secure_delete`. The database file and its `-wal`/`-shm` files are narrowed to `0600` on every open, not only at creation.
- **Snapshot capture no longer trusts the page.** `localStorage` is read through the browser's `DOMStorage` domain for the origin the browser reports, not by script in the page, so a page cannot plant entries under another origin. Capture has a total budget of 48 MiB (below the 64 MiB sealed limit) and fails with a typed error that names it.
- **WebRTC cannot bypass the forwarder.** Browsers behind a forwarder get `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`; `--force-webrtc-ip-handling-policy` and `--webrtc-ip-handling-policy` are managed flags.
- **An oversized DevTools reply no longer retires a browser.** The worker's control connection is reopened after a closed connection (and by health probes) instead of staying dead; an origin whose storage reply is too large is skipped. New `runtime.cdp_max_message_bytes`.
- **Secrets are zeroized and key files are strict.** `Secret`, the rendered `Proxy-Authorization` header and SOCKS5 credentials are wiped on drop; the snapshot key is passed by reference as a `Zeroizing` buffer (`Sealer::new` takes `&Zeroizing<[u8; 32]>`). A key file must be owned by the current user and be `0600` or stricter (group access was only a warning); new key directories are created `0700`.
- **Startup timeout is bounded.** `runtime.startup_timeout_secs` above 600 is rejected, and the launch deadline uses checked arithmetic, so a huge value can no longer panic the launching task.

### Known limitations

- The relay and the API speak plaintext `ws://` and `http://`; terminate TLS in front for anything beyond loopback or a trusted network.
- Shared-browser isolation is not a boundary against hostile tenants.
- Snapshots can be opened only by the active key or a key listed as retired; a snapshot sealed with any other key cannot be restored.
- Snapshots do not carry the JavaScript heap, `sessionStorage`, IndexedDB, Cache Storage, service workers, open sockets or origins that were never opened.
- Profile directories are not portable between machines or Chromium versions.
- Configuration is read at start; there is no hot reload.
